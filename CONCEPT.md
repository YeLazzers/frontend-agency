# Frontend Agency — Концепция

> Апрель 2026. Статус: зафиксировано, в реализации.

## Идея

Полуавтономная AI-команда для разработки фронтенда. Человек ставит задачу и ревьюит финальный результат — агенты делают всё между этим: планируют, пишут код, проверяют.

```
Человек → Architect → Engineer → QA → Человек
            SPEC.md     код      ревью
```

---

## Команда агентов

**Architect** — думает, не кодит. Получает описание фичи, отдаёт структурированную спеку: какие компоненты, какие TypeScript-интерфейсы, какой стейт, какие паттерны. Отвечает на вопрос *что строим и как устроено изнутри*.

**Engineer** — строит по чертежу. UI и State единая роль — в современном React компонент, хук и стор это одна единица работы. Знает когда взять shadcn-компонент, когда написать свой, когда Jotai-атом, когда React Query.

**QA / Reviewer** — сомневается во всём. Проверяет TypeScript strict (нет `any`), accessibility, edge cases, консистентность с остальным кодом. Выдаёт approval или список замечаний обратно в Engineer.

## Стек

| Слой | Технология | Решение |
|---|---|---|
| Фреймворк | React 18+ | |
| Язык | TypeScript strict | нет `any`, нет `unknown` без type guard |
| Стили | TailwindCSS v4 | |
| UI-компоненты | shadcn/ui + Radix UI | copy-paste, владеем кодом, a11y из коробки |

| Роутинг | React Router v7 | |

Выбор стейт-менеджера — pluggable: проект указывает `state: jotai` или `state: zustand`, агент подгружает нужный skill-модуль. По умолчанию Jotai.

## Архитектура: упрощённый FSD

Feature-Sliced Design без слоя `widgets` — избыточен для pet-проектов и небольших SPA.

```
src/
  app/        ← провайдеры, роутер, глобальные стили
  pages/      ← page-компоненты (только композиция, thin)
  features/   ← бизнес-действия (LoginForm, AddToCart)
  entities/   ← бизнес-сущности (User, Product)
  shared/     ← ui-kit, utils, api-client, типы, хуки
```

Правило: импорт только вниз по слоям. `features` → `entities` → `shared`, не наоборот. Проверяется линтером (`eslint-plugin-boundaries` уже настроен в `@turbo-pets/config`).

FSD выбран именно для AI-агентства: правила explicit и машиночитаемы — Architect и Engineer точно знают куда положить любой артефакт.

## Макеты и дизайн

Figma MCP умеет только читать файлы, не создавать. Подход по приоритету:

1. ASCII-схема в спеке — почти бесплатно по токенам, достаточно для Engineer
2. Именованные shadcn-компоненты — "Card с Avatar и двумя Button внизу" Engineer понимает без картинки
3. v0.dev — для сложных UI-кусков, выдаёт готовый React+shadcn код по описанию
